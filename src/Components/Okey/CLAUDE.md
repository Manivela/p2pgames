# Testing Okey

Rules (vitest, `npx vitest run`):
- Rules are pure functions in `game.js`: `(state, player, ...args) => newState | "toast message" | undefined` (no change). `OkeyContext.jsx` only wires them to Yjs. New rules go in `game.js` or a pure sibling like `checkFinish.js`, with tests.
- Pattern in `game.test.js`: `seated(n)` for an unshuffled table, `game.startGame(state, { okeyTile, hands })` to deal a known position.
- Rulesets: a game's numbers and switches (rounds, hand size, scores, takes, catch penalty) are a preset in `rulesets.js` (`AMERICANO`), stored in the game state as `rules` (its own sync key) and read from there by every rule, so a game keeps the rules it started with. A classic game has `rules` null.
- 101 (`ONE_O_ONE`, pagat.com's rules): opening by points counts the melds as laid out on the rack (a gap or a tile left out separates them, an okey counts where it stands), or 5+ pairs anywhere (`openingOf`); runs don't wrap (`wrapRuns`); no out-of-turn takes; a discard taken must go into a meld that turn or back on its pile (`tookDiscard`, `returnDiscard`); okeys on the table stay put; penalties during play collect in `penalties`; a hand nobody finishes scores only okeys held and the penalties during play, and is dealt again (`replay`). Tests in `oneOOne.test.js`. Not yet: finishing with all 21 tiles in one turn (−202 / 404 / 808), and the 101 penalty for taking back tiles after a failed opening.
- Americano: küt/seri checks in `melds.js`. `americano.*` wraps `game.*` for the moves that differ (start, discard, finish); `americano.startGame(state, deal, rules)`. Tests in `americano.test.js`.
- A discard can be claimed before the current player draws: `upForClaim` gives the discard up for claim, the offer once they draw from the pile. A table okey's value is fixed by where it sits (`okeyStandsFor`); a seri keeps the order it was laid in off the rack.
- Tile id `${color}${rank}-${copy}` (`red7-0`, fake okey `yellow👌-1`). `okeyTile` is the indicator; the okey is the next rank in the same colour. A hand has 26 slots (13 per row); `null` is a gap, and gaps separate groups.

End to end (Playwright Test):
- `npm run test:e2e` runs everything in Playwright's Linux Docker image (`e2e/docker.sh`, image version = `@playwright/test`'s), so screenshots render the same on every machine and in CI. Its Linux node_modules live in the `p2pgames-e2e-modules` volume. The image is ~1 GB to download (3.5 GB unpacked): the first run fetches it; `docker image rm` it when Docker's disk is tight. A plain `npx playwright test` on the Mac (~15 s; once: `npx playwright install chromium`) runs the same tests but skips screenshot comparisons (`ignoreSnapshots` off Linux).
- `e2e/okey.e2e.js` runs on a phone and a small phone (Turkish, touch) and on desktop (English), against the dev server (it starts one if none is running). Each table stage (lobby, play, menu, round end, classic, 101) must have no overlapping or off-screen parts and match its reference screenshot; behaviour tests cover drag to open, moving picked tiles, seats between rounds and save codes.
- Positions come from `e2e/table.js`, run in the page: the real rules on a fixed deal, written with `window.okey`, so every run looks the same.
- After an intended visual change: `npm run test:e2e -- --update-snapshots`, look at the new images in `e2e/okey.e2e.js-snapshots/`, commit them. A change within Playwright's per-pixel tolerance keeps the old image; `--update-snapshots=all` rewrites every one. Screenshots paint the felt flat (`e2e/screenshot.css`): its grain and dithered light made each PNG ~6x bigger.

Design:
- Prefer gestures to buttons wherever one fits: drag picked tiles onto the table to open, drag a picked tile to move the whole pick, hold to flip. Moves that end or replace the game (new game, reset, stand, load, set up a game at any round) live in the ⋯ table menu (`TableMenu.jsx`) behind a second tap.
- Table (`Board.jsx`, `Rack.jsx`): one layout for every screen, a CSS grid; only the size changes. Everything is sized in tile widths: `--t`, set on the page by `useTileSize` (as big as the box allows 16.8 tiles across and 7.4 down, up to 70px), so the flying copies, the dragged tile and the site's corner buttons match. Along the top: the site's ☰ and fullscreen (`root.jsx`, fixed; the row keeps their corner free) and the game's Scores and ⋯ at the two ends, the others' `Seat`s in seat order between them (your left neighbour first), each `DiscardPile` between the player who throws to it and the one who takes from it. The table: the draw pile on the left; where the round stands (`RoundInfo`) and the next step (Start, Next Round, New Game) on the right; between them the melds, the others' hands at round end (`Hands`, gaps kept) or, before a game, Copy invite link. Along the bottom: the pile you take from, your `Rack`, the pile you throw to. Anything that comes and goes (badges, the tea glass, Catch) is placed absolutely, so the row it's in never shifts. Phones held upright get "turn sideways".
- Whose turn: an amber name, a ring around their avatar (a glow around your rack) and a tea glass in front of them (under the avatar, beside your name). The ring is a 30 s timer (CSS only, `.timer`, keyed by deal and turn so it restarts): it loops, never skips anyone, and turns red after the first lap. Nothing about it is synced; each device starts it when the turn reaches it. The e2e screenshots freeze it (`e2e/screenshot.css`).
- Moves animate (`moves.js`, called by `Board`): each render compares where every tile is with the last render (tiles keep their ids within a deal) and flies a copy there, in a fixed overlay over the page (screen rects; the small piles, melds and shown hands use `zoom`, which Chrome and WebKit both report in them). Targets are found by `data-tile-id`, `data-seat`, `data-pile`, `data-meld`, `data-hand`; your rack's slots by position. The tile you just dragged (`dragged` in `OkeyContext`) only bounces. Skipped under reduced motion, after the tab was hidden, and for catch-ups (more than one discard or 20 tiles in one change). Dev-only `window.okeyFlights` counts flights for tests.
- Tiles: the colour is a `c-<colour>` class from the id, with a symbol per colour (`constants.js`). The hex in a tile is game state (saves, `melds.js` compares it): leave it. A face-down tile renders no colour or number, only `.back`. Avoid Bootstrap 3's global class names on table parts (`.hidden`, `.label`, `.open`, `.fade`, `.table`…).
- Every device auto-saves the latest game it saw, in any room, to `localStorage` (`okey-save`, one slot) as a save code (`game.encodeSave`: deflated and base64'd, so hands aren't readable at a glance); loading seats whoever sits in each seat now (`game.restore`).
- Between games and Americano rounds every seat shows (`game.allSeats`), so people can sit down or be freed from the ⋯ menu. The next deal goes to every seat in the game, sat in or not (a phone that slept sits back down), plus new seats someone sat in, but not a seat freed from the menu (`left`) until someone sits there. A seat keeps its score whoever sits in it; a new seat starts at the worst total (`americano.nextRound`).

Multiplayer and UI (Playwright MCP):
- With the dev server running, open the same `/<room>/okey` in several tabs of one browser. They sync over BroadcastChannel, with no signaling. Log in per tab; login is in memory, so a reload logs out.
- Dev-only `window.okey` reads and writes the shared state. To play as any seat: `g = await import("/src/Components/Okey/game.js")`, then `okey.set(g.drawTile(okey.get(), seat, tile, slot))`.
- Shared state is split across Yjs keys by writer (`sync.js` `parts`), so simultaneous moves by different players both survive. New top-level state lands in the `turn` key; if another player can write it at the same time, give it its own key. Only a hand's owner writes it: tiles given to another player go through their `inbox`. Whole-game changes (start, new game, reset) go through `replaceState`. A client that hasn't received the doc yet writes to the `lobby` deal and never moves the `deal` pointer, so a rejoining phone can't wipe the game. To test real network sync, open the second player in `browser.newContext()`: tabs of one context sync over BroadcastChannel almost instantly.
- `dragTo` works with react-dnd. Tag the source and target with `data-*` first. Your own rack is the only `.rack` (the others sit in `.seat`s).
- Sizes: check a layout change at 1348×870, 1024×768, 820×1180, 844×390 and 667×320, in the lobby, mid-game, at round end and watching without a seat. Touch screens get react-dnd's touch backend, picked at load from `navigator.maxTouchPoints`. To test touch, open a page, call CDP `Emulation.setTouchEmulationEnabled` on it *before* navigating, then drag with `Input.dispatchTouchEvent` start / move / end.
- The claim wait: `americano.drawTile` / `discardTile` take an optional `now` (ms). Tests discard at `afterWait(s)`; scripted play passes `Infinity`.
- Text: rules and shared messages stay in English; the UI shows them through `t()` from `src/i18n.js` (Turkish on Turkish devices). A new message needs a Turkish line there, or `i18n.test.js` fails. To see Turkish in Playwright, override `navigator.language` with `addInitScript` before loading; CDP's locale override doesn't change it.
